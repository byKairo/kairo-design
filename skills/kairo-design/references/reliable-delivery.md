# 技术执行与可复查交付

这里只规定文件、依赖、内部修正和审核数据契约，不提供构图或字形设计。设计与视觉审核由当前路线负责。

## 最小任务记录

在本次任务目录记录目标 ID、用途、尺寸、所选路线/风格、输入与保留项，以及该路线的简短设计决定。实际提示词存入 prompts/；只使用图像工具本次明确返回的路径、字节或 URL，不猜测最新文件。同名文件采用新版本名；用户所给图像、候选和成品分别标明用途。

修改前查看原图并记录保留项，修改后同尺寸对照。生成式编辑不保证其他像素不变；逐像素保留必须使用获准的可控实现并实际验证。

## 技术预检

第一次技术导出前运行 `python3 scripts/platform_images.py doctor`，确认 Pillow 和色彩管理可用。若失败，使用宿主的依赖定位工具取得 Python 路径，再用该解释器运行相同命令；不把本机绝对路径写成可分发配置。没有可用运行时则报告依赖缺口，不声称已导出。平台文件以 [平台尺寸](platform-specs.md) 为准。

脚本拒绝已有目标文件、动画、任何裁切或放大、超容量、非不透明 JPEG 背景及超过 4000 万像素的源图/目标图。CMYK 等模式须经导出转换后再检查；损坏的 ICC 不静默丢弃后声称色彩已规范。像素与编码检查通过，不等于平台上传或显示裁切已经实测。

## 重试与放行

默认不设置固定修正次数。每张图审核未通过就继续内部修正或重构、再看实际结果，直到通过后交付，不因达到某个次数向用户询问是否继续。同类问题反复出现时改变方案或实现方式，不机械重复相同调用；局部错误修正，整体构思无力则重新设计。用户明确给出的预算、次数或停止要求，以及系统和工具限制仍须遵守。工具故障、额度耗尽、必要能力缺失等确实无法继续时如实说明阻塞，不能将未通过的图当作成品，也不能宣称绝对零缺陷。

每张最终文件须留下简短审核记录，绑定最终文件的 SHA-256：锁定文字或完全无字、内容与动作、风格机制、修改保留项（无修改可记不适用）、目标显示大小的可读性、技术检查。每项记通过/失败/未验证及实际可见依据。缺少证据记未验证，不能默认通过；哈希变化后重新检查受影响项。记录不能自行证明看图已经发生，也不能把模型自评当作独立审美验证。

同一任务记录另保留所选路线设计审核的实际观看重音、与预定任务的差异、保留或退回决定，以及修正前后最重要的变化。系列还需整体分工判断。这里不增加审美分数；设计仍要求调整、重做或未验证的文件不能因六项硬性检查齐全进入成品列表。已知方案问题不能仅记为注意事项后继续放行。

最终成品列表只包含全部必要条件通过的文件，并逐一对应原始目标与数量。风格对比按实际主导机制辨识；一张成功图、风格静态校验或没有错字都不支持总体稳定率。

## 最终文件机械检查

实际看图后，在本次任务目录保存 `brief.json` 与 `review.json`，运行 `python3 scripts/final_gate.py --brief brief.json --review review.json`。这里的路径是任务文件，脚本从 Skill 的绝对路径调用。脚本不读取其他任务目录，不上传、不修改图片；结果中的 `visual_truth_checked_by_script` 恒为 false，不能称其自动证明审美或文字像素正确。

`brief.json` 的 `targets` 是数组，每项包含唯一 `id`、正整数 `width`/`height`、`style`、`text_policy`（`exact`/`none`/`keywords`/`unspecified`）；`exact` 还须含完整画内文案 `locked_text`，按阅读顺序拼接所有标题、辅助短句和标签，保留有意义的空格及标点；仅排版换行不计入，原文自带换行仍保留。修改目标设 `edit: true`；平台已知时填对应 `constraints_preset`，例如 `xhs-note`，以便读取预设容量。

像素未由用户指定时，生成前记录目标 `aspect_ratio`，生成后核实比例并将真实像素填入 `width`/`height`；这些字段用于绑定交付文件，不是固定分辨率预设。自定义比例须显式填写 `aspect_ratio`，否则最终检查沿用 `constraints_preset` 的比例。

有字图另填`title_text`，表示完整最终标题；有用户原标题时填`source_title`，内部拟题时不伪造来源标题。两者不同须填`title_change_approval: {"approved": true, "evidence": "用户同意的实际消息或可追溯记录"}`。`review.json`逐字记录`observed_title`，与`title_text`核对；`observed_text`仍与全部`locked_text`比较。标题校验与完整文案校验分别执行，不能为了消除辅助文案误报而删去辅助文案审核。旧任务仅有`locked_text`仍按完整画内文案核对。

每个目标还需声明`style_source`为`catalog`、`custom`或`technique`；前者用已选风格ID，后者包括有字纸面工艺兼容入口。`text_policy=unspecified`仅可用于未锁定文案的有字任务，并须写`mode=with-text`；普通无字任务必须为`none`，不能用`unspecified`跳过检查。`design_features`包含四个布尔字段：`collage`（拼贴）、`object_transformation`（形态/材料/功能/尺度转化）、`paper_finishes`（纸面压凹击凸）、`exact_typography`（可控排字），无使用记false。对自定义方向同样按实际设计评估；无字图仍只读取无字路线，不引入有字专项设计约束。

将一个目标对象保存为`target.json`，运行`python3 scripts/reading_plan.py --target target.json`获得必读资源相对路径清单。先读取再记录；整份阅读的文件也须列出已覆盖的小节键。每个审核条目的`readings`为实际已读资源键的数组，例如`routes/with-text/design-guide.md#text-led-design`。最终检查按路线、风格父项和专项使用情况计算必读集合，缺项不放行；它只能验证记录完整，不能证明阅读或理解发生。比例必须显式记录或由有效平台预设取得，二者皆缺失不能放行。

`review.json` 包含 `brief_sha256` 与 `items` 数组。每项包含 `target_id`、相对 review 文件所在目录的最终图片 `path`、最终图片 `sha256`、`observed_text`，以及 `checks`。在实际像素中观察到的文字须按阅读顺序记录；仅为排版产生的换行不写入 `observed_text`，原文已有换行则保留。完全无字记录空字符串。

`checks` 需有 `text`、`content`、`action`、`style`、`readability`、`preservation` 六项，每项含 `status` 与非空 `evidence`。必要项只有 `pass` 可放行；非修改任务的 `preservation` 可用 `not_applicable`，仍需说明没有修改保留项。无动作、纯文字或抽象图在相应项说明实际用途与成立依据，不编造场景判断。脚本检查文件哈希、条目、文字记录和真实像素；审核证据的真实性仍由执行者负责。

所有成图目标须含 `design_review`：`decision` 为 `retain`／`local_fix`／`reconstruct`，`evidence` 为当前图片的非空可见依据；只有 `retain` 可作为成品。`user_feedback_status` 可记录 `pending`／`accepted`／`rejected`，待反馈不阻止内部保留，明确否定则必须拦截。已有 `delivery_status` 中的明确否决同样拦截。`user_accepted: false` 本身不等于否决，不能因此增加等待用户批准的交付步骤。

最终检查只核对审核决定是否与交付一致，不替代看图或自动评分。明确失败时更新本任务状态，不修改风格身份或在正式 META 内堆积反馈履历。

## 用户可见交付

默认仅提供通过审核的独立成图、工具实际返回或本次确实保存的可下载文件链接，以及简短说明。内部提示词、构思比较、失败候选、阅读清单和审核记录不主动展示；用户明确要求时再提供。无法取得下载文件时说明实际可用的预览，不伪造下载链接。用户明确只要提示词时按其请求交付提示词。

## 文字一致性与关键词例外

完整标题必须同时包含在`locked_text`及`observed_text`中，不能只在`title_text`／`observed_title`单独声称正确。跨行展示检查时只忽略换行，不忽略标点或有意义的空格；全部文案本身仍逐字核对。字号和层级不影响完整读序。

仅目录`editorial-design`的无字路线可用`text_policy=keywords`。填`source_title`（原标题；没有原标题时为内部依据主题拟定的来源标题）、`allowed_keywords`（按阅读顺序排列的准确字词列表）、`keyword_origin`（内部提取为`extracted`，用户指定为`user`）；`locked_text`为词表依序拼接，`observed_text`为实际看见的所有文字，两者必须完全一致。不填完整画内标题字段`title_text`/`observed_title`，来源标题只作选择依据，不放入图中，也不触发完整标题改写审批。内部提取须来自来源标题；允许词表必须明显短于原标题，不能通过拆成词语或去掉标点来放入全标题。脚本拦截全标题长度和额外文字，审核者仍须判断是否只是少量重点字而非近乎完整标题。

该例外不开放给自定义风格或其他无字目录项；纯无字用户要求优先，不推荐关键词例外。设计阅读记录与实际看图要求保持不变。

### 比例检查策略

目标默认 `ratio_policy=approximate`，按生成画幅允许2%的相对偏差；工具回退时保留原 `aspect_ratio` 并填写 `generation_aspect_ratio`，常规近似不成为交付阻断点。用户明确严格要求或已核实硬性尺寸时用 `ratio_policy=strict`，不能用回退画幅覆盖严格目标。`width`/`height` 绑定实际交付文件；用户明确的像素要求必须另按其原值检查，不能用实测值替换要求。具体规则见[平台比例](platform-specs.md)。
